首选做**看球调整站位，再按指令射向左半门或右半门**。第一笔算力用原生行走任务测单卡吞吐，第一项技能训练用头部图像和已经会走、会踢的本地策略。两项可以独立推进。

## 为什么先练站位

在现有 CPU MuJoCo 球场里，冻结右脚、0.14 m/s 助跑 0.56 秒、停 0.24 秒的控制器。每个球位复用种子 58100–58107，初始关节抖动均为 ±0.001 rad。只在第一个物理步前改变球心平面坐标，沿用原裁判对指定脚触球、整球过线、动作完成、末段站稳和关节范围的要求。

| 球在身体前方 | 偏右 2 cm | 偏右 4 cm | 偏右 6 cm |
|---|---:|---:|---:|
| 16 cm | 8/8 | 8/8 | 1/8 |
| 18 cm | 8/8 | 8/8 | 0/8 |
| 20 cm | 7/8 | 5/8 | 0/8 |

72 回合中指定脚触球 71 次，完整通过 45 次。9 个摆位都没有初始机器人与球重叠，终止跌倒、限位违规和非有限数值回合均为 0。中心球位用原程序复跑也是 8/8。前方 18 cm、偏右 6 cm 这一格最值得练。8 次都触球并完成踢腿，6 次没有把整球踢过门线，另 2 次过线时球心已偏出允许范围。训练奖励因此应包含**有效进球**，诊断时分别记录没踢到、没过线和踢偏。

本地旧记录的 94/100 来自同一固定练习球位。新九宫格只用于定位难点，正式验收另抽连续球位和随机种子。用现有 NVIDIA EGL 头部相机在中心球位做了几何分割预检，320×320 图像中球占 3,762 像素，可从仿真生成可见框。光照、遮挡、俯仰变化下的检测率由后续视觉实验测量。[本地基线与原评分](simulation-results.md)

## 可做的训练，按优先级排列

以下数字是建议的阶段目标。

| 方向 | 具体训练方法 | 对照与验收 |
|---|---|---|
| 1. 看球选角射门 | 冻结低层步行和踢球，先练右脚。上层每秒决策 5–10 次，输出前进、横移、转向和起脚时机。先用球与球门相对位姿找出有效助跑动作，再训练头部 RGB 学生，最后加入左脚和目标半门口令。 | 固定助跑、用真实位姿对齐、只用图像对齐，三组跑相同球位。第一阶段在 200 个新球位上有效进球 ≥80%，且较固定助跑提高 ≥15 个百分点。第二阶段左右口令各 100 回合，各自命中目标半门 ≥70%。整球须在两柱内，目标半门由过线时球心侧别判定。 |
| 2. 打滑时也能拍稳的摄影鸭 | 从原生 `Velocity` 起步。课程依次为单一地面行走、途中跨摩擦分界、跨界时轻推。用速度跟踪、支撑脚滑移和机身姿态训练，再加一个头部稳像目标。训练时可用标记的几何投影评分，留出头部 RGB 回放验证。 | 与原生行走同地形、同扰动配对。目标为受推后 2 秒内恢复到指令速度 80% 的回合 ≥85%，跌倒 ≤5/100。在相同走速下，比较加稳像奖励前后的目标像素抖动。原任务已含脚底摩擦随机化和速度扰动，这里考察一步内跨材质及继续走。 |
| 3. 桌边冰壶 | 鸭嘴轻推红蓝块，在桌边停进指定圆环。用已有分段看图推送做教师，学生学习推向、推程和停止时机。依次变化摩擦、灯光、目标离边距离，再加入不能碰的干扰块。 | 与本地 98/100 的规则控制器在**同一套新难度**重跑。首轮 100 个保留摆位入圈 ≥85、掉桌 ≤2，另外报告干扰块位移和每回合推数。固定桌面台架，全程纯接触。 |
| 4. 八拍定格舞 | 从 `SitStand` 和命令步行组合点头、横移、下蹲、起立。先练两个动作之间平滑切换，再加节拍相位。奖励节拍误差、姿势和结束站稳，同时记录峰值越限。 | 与直接按拍切换动作的脚本对比。目标为 100 段中 ≥80 段在 ±150 ms 内完成八拍、末拍站稳，越限回合为 0。已有本地起坐完成动作 10/10，但完整限位验收为 0/10。 |

## 足球主线怎样得到第一版可用策略

1. **先找一套能踢进的动作。** 在 9 格附近连续采样。对难球位试横移、朝向和起脚时机，按裁判结果保留成功与失败轨迹。以同种子固定助跑为对照。用仿真真值对齐后仍经常失败的球位优先改站位或动作集合。
2. **再让头部相机接班。** 以球、门柱/目标区的可见分割生成方框，包括球被挡住或不在视野的负样本。给球和门柱加稳定的可区分外观，加入光照、材质和相机俯仰扰动。先生成约 5,000 帧，把场景种子按训练/验证/测试划分，再抽帧。复用上游 320 像素 YOLO 脚本，从 batch 16 起测。颜色阈值、真值框、学到的检测器都接入相同控制器，用最终进球率判断换模型的收益。
3. **让 GPU 学习决策。** 先用成功对齐轨迹监督训练小型上层策略，再把学生自己走到的失败状态交回教师纠正。策略输入为球/门的图像测量、置信度和本体状态。丢球时学会停和重新搜索。保留原低层 50 Hz 控制和踢球策略的逐环境循环状态。只有要做在线 PPO 微调时，才把上层球场和低层推理移植到 GPU 批环境，先用固定输入、单回合回放对齐 CPU/GPU 动作与裁判。
4. **跨球场复测。** 上游训练球为直径 70 mm、15 g，本地练习球为直径 100 mm、30 g。先在相同球规格、门宽、执行器标定和初态下比较算法，再把另一套规格作为迁移测试。两个机器人 XML 的 SHA-256 也不同，接新 ONNX 时逐项核对关节顺序、HOME、IMU 轴、动作缩放、归一化及接触几何。

拿到第一批带框图像后，在装有上游 `requirements-vision-train.txt` 依赖的独立环境运行。把 `DATA_YAML` 设为实际标注配置的路径，先用 10 个 epoch 看留出场景的球心偏差和漏检率。训练脚本会导出 320 像素的 ONNX，供完整点球回合复测。

```bash
python scripts/vision/check_dataset.py "$DATA_YAML"
python scripts/vision/train_detector.py "$DATA_YAML" \
  --device 0 --imgsz 320 --batch 16 --epochs 10 --seed 42 --name football_pilot
```

## 这张显卡怎么排训练

主机为 i7-14650HX、31 GiB 内存、RTX 5060 Laptop。当前工作区的 Python 3.12 环境已有 MuJoCo 3.3.7 和 CPU 版 ONNX Runtime 1.23.2。上游锁定 Python 3.12、mjlab 1.3.0、MuJoCo 3.10.0、MuJoCo Warp 3.8.1、Warp 1.12.0 和 PyTorch 2.9.1。上游使用独立虚拟环境，本机当前 PATH 中需要先准备 `uv`。此计划的 PPO 并行度和 GPU 小时均按待测量预算处理。

**第一段先测吞吐。** 在上游独立 checkout 根目录执行，环境安装时间和首次 Warp 编译单独计时。

```bash
uv sync --frozen
uv run --frozen python -c "import torch, warp as wp; wp.init(); assert torch.cuda.is_available() and wp.is_cuda_available(); print(torch.cuda.get_device_name(0), wp.get_device('cuda:0'))"
uv run --frozen list-envs
uv run --frozen train Mjlab-Velocity-Flat-Wonderduck \
  --env.scene.num-envs 64 --agent.max_iterations 5
```

确认原生行走任务能推进、损失及观测有限、可以保存模型。若 `list-envs` 只注册了一部分任务，先查看 WonderDuck 插件抛出的首个错误并检查主存。随后手动逐档把环境数升到 **128 → 256 → 512**，显存仍宽裕且吞吐继续提高时再试 **1024**。每档用同一个任务和种子，各跑 40 次更新，剔除前 10 次编译/预热，记录后 30 次的中位表现。每个档位启动一个训练进程，训练时关闭录像。示例为其中一档。

```bash
uv run --frozen train Mjlab-Velocity-Flat-Wonderduck \
  --env.scene.num-envs 256 --agent.max_iterations 40 --agent.run-name bench256
```

另一个终端可用这一行每秒采样整卡显存、功率与温度。在训练日志中同时取 rollout 秒数和 PPO 更新秒数。

```bash
nvidia-smi --query-gpu=timestamp,utilization.gpu,memory.used,power.draw,temperature.gpu --format=csv -l 1
```

行走默认每个环境每轮采 24 个控制步。**有效吞吐 = 环境数 × 24 ÷（采样秒数 + 更新秒数）**。例如 256 环境是 6,144 步/轮。留约 1 GiB 给显示桌面和短时显存峰值，选择接近最高吞吐的最小档位。若加倍并行仅多出不到 10% 吞吐、出现 OOM 或热稳态吞吐回落，优先选前一档。视觉、粗糙地形和密集接触的任务各自重新测档。图像离线成批训练，单卡一次运行一个主要训练任务，CPU 可以同时生成动作轨迹或跑无录像裁判。头部 RGB 的 EGL 渲染与 PPO 都会占用同一张卡，优先分时运行。

**第二段用首批 8 个 GPU 小时作预算。** 依赖、任务代码及首批数据准备好后，预留约 1 小时给环境与并行度标定，约 4 小时给原生行走和地面变化基线，约 2 小时给足球视觉与上层模仿，约 1 小时给最佳候选的重复或补测。先保留 250、500 轮一类的早期检查点，按实际吞吐调预算。行走学习是否有效看保留路线上指令误差与跌倒率，足球看保留球位的阶段成功率。正式比较双方使用相同训练转移数、相同课程阶段和相同干扰集合，保留 3 个训练种子的各自结果。记录提交、配置、环境数、种子、检查点、每秒步数、峰值显存，以及同一个失败种子的回放。

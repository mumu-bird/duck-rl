# 全部音频功能验收清单

交付基线：2026-11-23。浏览器“验收记录”页可以逐项记结果、现象和备注并导出 JSON。单次播放的 `audible_verified` 始终不伪造听觉结论；人为实机观察记录在验收表。

## 当前证据边界

软件自动测试覆盖真实音频导入转码、真实中文 TTS、API、调度、并发、错误处理、原厂桥接、功放包装器契约、录音子进程管线与可回滚安装。无头 Chrome 用隔离配置和合成麦克风测试网页，不使用用户真实麦克风。MuJoCo 的站立、前行回合实际执行并产生音频事件。

当前没有机器鸭连接地址或 SSH 配置，未部署到机器人。真实扬声器出声、首字、音质、音量、机身麦克风、运动并行、原厂提示音实机共存与嘴部标定均保持待验收。原有训练测试还受本机缺少 PyTorch 限制；这与音频依赖无关。

本机测试证据保存在项目 `runs/audio-acceptance/`：`software-test-report.json`、`browser-test-report.json`、`console-desktop.png`、`console-mobile.png`、`task-suite/audio-events.jsonl`、`acceptance-report.json`。详见同目录生成的报告；不要把模拟后端完成状态当成实机听到声音。

## 逐项操作

| 项目 | 验收操作 | 通过条件 |
|---|---|---|
| 1. 资源管理 | 分别上传 WAV/MP3/M4A/OGG/FLAC，中文命名、改资源键、下载、删除；再上传损坏文件、重复 key | 有效文件可播放；下载为规范 WAV；坏文件/重复 key 明确拒绝，失败不遗留资源 |
| 2. 播放控制 | 播放一段 10 秒音频，中途暂停、继续、跳到第 5 秒，再停止 | 状态和位置正确；停止后无继续声音；重复停止安全 |
| 3. 队列 | A 播放时排队 B；尝试三次重复、无限循环、忙时拒绝、替换同任务、短 TTL | 顺序和次数符合配置；循环能停止；过期声音不再播；满队列返回明确错误 |
| 4. 任务模块 | 运行拾取或任务套件；触发目标事件多次；启动另一实例；只取消第一实例 | 阶段播报来自真实事件；去重有效；取消不影响其他实例；音频故障写日志且不改变动作判定 |
| 5. 中文 TTS | 输入中文短句，生成并播放，再生成完全相同文本/声音/语速；更换语速 | 可听懂的离线语音；重复命中同资源；无需网络；保存后可按资源键调用 |
| 6. 浏览器录音 | localhost/HTTPS 上允许麦克风，录 3 秒，停止保存，再回放；拒绝权限后重试 | 文件真实保存，授权/拒绝反馈清晰，停止后麦克风占用释放。自动测试只用合成输入 |
| 7. 扬声器与首字 | 连续听默认五句话，首段从静置功放开始；测试不同音量 | 首字完整、无明显爆音/削波/中断，声道和功放行为正确 |
| 8. 音量 | 30→70→静音→恢复；修改后重启音频服务 | 实际音量变化；静音有效；重启恢复用户设置；失败不显示假成功 |
| 9. 机身麦克风 | 停止声音后录 5 秒，提前停止、自动到时、保存后回放；正在播放时尝试录音 | 收到机身真实声音，保存文件可复用；录放冲突有明确反馈；无遗留 arecord |
| 10. 运动并行 | 在站立、行走和自主任务执行期间调用新音频 API；停止此任务音频 | 不因音频夺取运动控制权；控制周期与动作正常；停止音频不造成全局急停 |
| 11. 原厂系统提示 | 重启确认开机音；播放任务长音期间由原厂受控测试入口触发低电量提示；结束后再播普通音 | 告警抢占新队列低优先级音频，临时音量结束后恢复；禁用/故障回退原厂；不修改电池保护阈值 |
| 12. 嘴部联动 | 在现有授权控制器中提供标定回调并允许嘴部动作；播音、暂停、取消和失去控制权 | 嘴型随包络变化；暂停/结束关闭；不越界、不夺取控制；抓取阶段不因播报张嘴 |
| 13. 异常与恢复 | 播放中重启音频服务、断开客户端；缺失播放器；上传中断；重复安装与回退 | 未完成任务标为失败且不自动重播；音频库与设置保留；错误可见；所有子进程/锁释放 |

板端系统提示验收不需要耗尽电池，也不要通过修改电池关机阈值完成测试。可通过原厂专门的提示音测试方式触发；是否对应本机固件需先核对。仅在软件队列调用 priority=100，不能替代原厂低电量触发链路的验收。

## 本机复现命令

```bash
.venv/bin/python tools/check_audio.py
node tests/audio/web-smoke.cjs
.venv/bin/python tools/run_suite.py \
  --output runs/audio-acceptance/task-suite-new \
  --episodes 2 --tasks stand walk_forward --seed 241123
python3 tools/build_audio_release.py
```

网页测试脚本使用系统 Google Chrome 与外部测试依赖 `playwright`，默认路径为 `/tmp/wonderduck-audio-browser/node_modules/playwright`；可用环境变量 `PLAYWRIGHT_MODULE` 指向已有安装。依赖仅用于开发机验收，不是板端运行依赖。脚本需要已启动的本机模拟服务和默认资源。

验收失败时，在网页记录对应项目为“未通过”，备注写入任务 ID、时间、实际现象和设备日志；不要通过切换到模拟模式来使硬件项目通过。

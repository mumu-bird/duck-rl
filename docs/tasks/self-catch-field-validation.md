# 自抛接球现场验收单

**这次不能验收真机自动接球。** 本机还没有接入鸭子热点；当前冻结策略也没有可安全直接下发的真机视觉、步态与嘴部时序接口。本轮没有连接设备，也没有向舵机发动作。不要把 `.pt` 上传到 Studio，不要改现有走路、站立或拾球模型槽。

## 现场：一条命令

1. 鸭子放在平地，双腿舒展、不叠放，嘴里不放球。按原厂手册开机并等它播报序列号（约 30 秒）。
2. 在电脑 Wi-Fi 列表选择这只鸭子 `WD-` 开头的热点，默认 Wi-Fi 密码为 `hiwonder`。确认电脑不是仍连着办公室/家用 Wi-Fi。
3. 在这台 Linux 电脑的终端运行[现场检查包](../../delivery/selfcatch-check.pyz)：

   ```bash
   python3 -I -B -S "/home/harrisonwang/文档/ChatGPT/wonder/delivery/selfcatch-check.pyz"
   ```

默认命令不需要账号、不启动浏览器或动作库，只读检查并在包旁生成一个新的 `reports/field-*.json`。它先检查 Linux 本机路由：若目标经网关转发而非直连热点，会**在发送任何设备请求前停止**。需要确认实际舵机诊断时，再自行打开原厂 Studio 的“设备状态”页人工查看；脚本不会替 Studio 注册状态订阅。

| 屏幕输出 | 现场如何判断 |
|---|---|
| `BASIC_READONLY_OK` | 已确认非演示设备、三次连续状态、IMU 和电压/低压保护数据正常。可以记作“基础遥测通过”，不是舵机动作、安全限位或相机验收。 |
| `PASS_READONLY` | 除基础遥测外，匿名接口还公开了 15 个新鲜、无故障的实测编码器反馈。仍不是舵机动态限位或相机检查。 |
| `CHECK` | 接口有响应，但有缺失、过期、告警或版本/字段不符。看报告原因。缺少公开编码器诊断不等于舵机坏了；不要为通过检查而使能舵机。 |
| `NO_LINK` | 没有发请求或没有连到目标。先确认电脑连的是 `WD-` 热点，再重跑命令；只读路由失败时，不必改鸭子配置。 |
| `BOARD_POLICY_PASS` | 仅在显式提供已知 SSH 账号时，才在自报 RK3566 的板上计算固定仿真输入；1,200 个输出与原 PPO 一致。不是实时看球、不是动作测试。默认一条命令不会 SSH。 |
| `NOT_TESTED` | 实体接球没测；上述只读项目通过也不会改变这一项。 |

工具只用匿名 `GET /api/info` 和 `GET /api/state` 读取公开状态；不注册 Studio 工作区、不接管其他客户端、不保存令牌。完整的舵机诊断流可能只在原厂“设备状态”页可用。已连对热点仍无响应时，可在浏览器打开 `http://192.168.149.1:8090` 核对原厂页面。

有这台板的可信 SSH 账号，才在同一条命令末尾追加 `--ssh-user 已确认账号`；没有就跳过。首次连接应先核实主机密钥，热点密码不是 SSH 凭据。回放程序通过标准输入运行，不安装文件、不连接运动服务。在电脑上离线自检则只需在同一条命令末尾追加 `--offline`。**现场退出码**：0 表示完整的只读诊断通过（如选了板端回放也必须通过）；1 表示有缺项或告警，即使基础读数正常也不会返回 0；2 表示无连接或报告未保存。任何退出码都不表示实体接球通过。

## 为什么不下发动作

| 仿真设置 | 空中接回并夹稳等全部条件通过 |
|---|---:|
| 未训练 / 六路 PPO 训练后，原控制方式、相同的 100 个留出起点 | 0/100 → 100/100 |
| 冻结 PPO + 随包步态、20 ms 嘴部指令 | 0/100（仅 1 次再次碰嘴，100 次都落地） |
| 冻结 PPO + 20 ms 直接指令 | 0/100 严格成功 |
| 在随包步态、20 ms 嘴部指令上再练 40 轮 PPO，以确定性动作验 100 个新起点 | 0/100（48 次再次碰嘴、0 次夹稳、全部落地） |

原任务从嘴里已有 20 mm、2.5 g 的球开始；原仿真中位数是球前移 29.1 mm、鸭身前移 9.7 mm、飞行 95 ms，不是长距离奔跑。迁移微调在 16 个另设验证种子上选中第 37 轮；留出回合里离嘴后的升高最大仅 0.375 mm，裁判要求 12 mm。在原模型上另做的 20 ms 时序对照、以及 50 Hz 的 CEM 残差优化，也都没有严格达标。以上都是仿真，不是对实机成功率的估计。

打包时电脑的本地路由指向办公网网关，不是机器鸭热点直连。本机离线自检和断网拦截均不能作为实机结果。

**下一次实体动作验收需要什么：**先对照这只鸭子的实际步态与舵机映射，测量嘴、头和颈的限位及响应时序；用同步视频把球的位置、速度与延迟接到策略输入；让按实测时序运行的策略先通过同一套仿真判据，再做有停止保护的实机试验。一次启动后应由鸭子自己抛、追、在触地前接住并持续夹稳，由侧面视频记录。人工按键配合、落地拾起都不算。旧拾球任务继续独立保留，本轮没有写入它的代码或权重。

相机与实机策略的补全步骤、已准备的相机采集命令见[真机补全说明](self-catch-completion.md)。相机采集仍不等于视觉闭环或实体接球通过。
